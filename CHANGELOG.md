- **BDD (`playwright-bdd` 9.2.1, pinned)**: `registerApiSteps` (send requests, auth, headers, query, bodies, uploads, GraphQL, polling; assert status, headers, fields, JSON subset/schema, timing; remember values), `registerDataSteps` (variables, random data, dates, env), `{{placeholders}}` everywhere; `vars` and `apiScenario` fixtures; a `bdd` project and sample features in `features/`; `npm run test:bdd`.
- **`api-curl-to-playwright`**: turns curl commands (a file, a folder, or stdin; bash or Chrome "Copy as cURL" cmd form) into tests that use `apiClient`, the auth classes and the response assertions. `# name / expect / expect-json / expect-header / expect-max-ms / schema / save / flow / tag / skip / secret` comments above a command say what to check; values it recognises as secrets are read from the environment instead of being written (see Changed (behaviour): this is not a guarantee); `--param` marks more. `toCurl()` goes the other way. The generated test starts with `CONSTANTS` (every query, header and body sent, every expected status/field/header/timing; secrets as environment getters) and `ENDPOINTS` (the path of every call) and its steps only refer to them, so a changed input or URL is one edit at the top (`--inline` writes them in the steps).

- **`expect` matchers** for an `ApiResponse`: `toHaveStatus`, `toBeSuccessful`, `toHaveJsonPath`, `toMatchJsonSubset`, `toMatchJsonSchema`, `toHaveResponseHeader`, `toRespondWithin`.
- **Auth**: `OAuth2PasswordAuth`, `JwtAuth`, `HmacAuth`, `SessionCookieAuth`, `CompositeAuth`.
- **Fixtures**: `apiFor` (a client for another user/system), `cleanup` (newest-first undo), `attachExchangesOnFailure` (the calls a failed test made, as an attachment).
- `docs/PLAYWRIGHT_COVERAGE.md`: Playwright's API-testing capabilities against the framework, with the gaps this round closed.

### Changed
- **API behaviours are tested as Gherkin scenarios**: the plain specs that exercised an API behaviour (each HTTP method, forms/XML/uploads, authentication schemes and their login/refresh/session handling, retries and their report notes, paging, GraphQL/SOAP/redirects, a gateway base URL, the mock service) were converted to features in `features/` (new: `http-methods`, `authentication-schemes`, `authentication-resilience`, `retry-policy`, `paging-through-results`, `paging-fails-loudly`, `protocols-and-redirects`, `base-url`, `mock-service`; extended: `authentication`, `users`, `resilience`, `request-bodies`) with new steps in `features/steps/` (not in the shipped `src/bdd`); `tests/pagination.spec.ts` is gone and the converted tests were removed from `apiClient`, `apiAdvanced`, `auth`, `baseUrl` and `mock/mockServer` specs, which keep the library-level tests. The drift guards, the converter and its generated example, the fixtures and remote specs, the response/step oracles and the page-based mock specs are unchanged. `--grep @smoke` / `@regression` select the same behaviours as before.
- **tsconfig works with TypeScript 7**: `"module": "node16"` and `"moduleResolution": "node16"` replace `commonjs` / `node` (TypeScript 7 removed `moduleResolution: node` and stops with TS5108). The compiled JavaScript is identical; checked with TypeScript 5.9.3 and 7.0.2. The fortnightly audit flags the old setting (`tsconfig-removed-option`).
- Docs and CLI usage text: inside this repo the converter is run as `npm run curl-to-tests -- <args>` (or `node dist/cli/curlToTests.js <args>` after `npm run build`); `npx api-curl-to-playwright` is documented only for a project that depends on this package. Environment variables, the setup / publish scripts and the clipboard example show PowerShell next to bash (`$env:ENV = "stage"; npx playwright test`, `.\scripts\setup.bat`, `Get-Clipboard | npm run curl-to-tests -- - --stdout`); the `scripts/*.bat` texts name the `.\scripts\...` form and the registry in PowerShell form.
- The committed `.env.dev` / `.env.qa` / `.env.stage` say which of their lines have no effect (`ENV` chooses the file; `LOG_LEVEL` is read from the real environment only).
- **`@automation/referenced-automation-utils` is a version range (`^1.0.0`)**, installed from the registry in `NPM_REGISTRY_URL` (`setup` runs `npm config set registry` first); `setup.sh --local` installs locally built tarballs instead; `scripts/publish-package.sh|.bat` publishes this package. The pipeline no longer clones sibling repos. README: publishing, upgrading, local generation.
- **Playwright 1.64.0** (was 1.62.1): the `@playwright/test` / `playwright-core` floor is `^1.64.0` and the peer range is `>=1.64.0 <2.0.0` where the package declares one; run `npx playwright install chromium` after upgrading.
- `playwright.config.ts` uses the shared `createPlaywrightConfig`; the duplicated SMTP/SFTP test servers are gone (use `testing` from utils).

### Changed (behaviour)
- BDD steps that name a FULL URL (`When I send a GET request to "http://other-host/x"`, `I wait until a GET request to "{{otherApi}}/x" ...`) call that host on purpose: the client's refusal of absolute URLs applies to code that builds a path from data, not to a URL the feature author wrote out.
These are stricter defaults (the package is unpublished at 1.0.0, so no deprecation period); each one turns a silent wrong answer into a failure.
- **`ApiClient` URLs**: a path is JOINED to the base URL and keeps the base URL's path (`https://gw/api/v1` + `/users` is `https://gw/api/v1/users`; `new URL('/users', base)` used to drop `/api/v1`, so tests hit the wrong endpoint and negative tests passed). A full URL in place of a path now THROWS unless the call passes `absoluteUrl: true` (it used to override the host and receive the client's auth and headers); the curl converter writes `absoluteUrl: true` for the full URLs it keeps. A `{placeholder}` in a path with no `pathParams` now throws. A query written in the path is merged with `queryParams` (Playwright used to let `params` replace it). Signing providers sign the path as sent, base-URL prefix included.
- **`apiClient` fixture** is built on Playwright's `request` fixture and reads `.env.<ENV>` from the folder of the Playwright config (not the working directory); its base URL is `use.baseURL`, else `API_BASE_URL`. `apiFor` no longer passes `undefined` options that hid the project's own (`ignoreHTTPSErrors`), and no longer inherits the main client's credential default headers (Authorization, Cookie, API-key style); neutral headers are still copied.
- **Auth providers**: token / login calls go through the client's connection (proxy, TLS, timeout; in `exchanges()`), have a `timeoutMs` (default 30 s; `fetch` with `AbortSignal.timeout` outside a client), are single-flight (parallel requests share one token request / login), and a failure message shows only the OAuth `error` / `error_description` (credentials masked) instead of the identity provider's body. A token response without `access_token` is an error. `SessionCookieAuth` logs in again once on a `401` (new optional `AuthProvider.reauthenticate()`).
- **Pagination**: a non-2xx page throws (page number, status); hitting `maxPages` with more data left throws unless `allowTruncation: true`; an empty-string cursor ends the loop; a repeated cursor throws; an items path that is not an array throws.
- **Assertions**: `expectNoGraphqlErrors()` needs a JSON response with `data` or `errors` (an HTML 502 / empty body / `{ "data": null }` fails). XML parsing keeps values as text (`00123` stays `'00123'`; numbers and attributes are strings now: compare with `'7'`). BDD `the response field ... equals "1"` is typed (the string "1", not the number 1 or true); new `equals 1` (number) and `equals "1" as text` steps; `is not empty` also rejects `{}` (a number, `0` included, or `false` is a value). Existing features were updated.
- **`pollUntil` / `client.poll`**: the default limit is 30 s but at most 80% of what is left of the test timeout; the error reads `Poll timed out waiting for ...; last response: ...`.
- **Exchange log**: `exchanges()` stores response headers masked (`Set-Cookie`), XML element values and attributes by name, numeric secrets (`password: 123456`) and objects under a secret name, token-like URL path segments (`safeUrl`), and URLs inside error messages. Calls that needed retries add an `api-retries` test annotation.
- **Recorder**: `recordApiTraffic` redacts at record time (credential headers masked, `Set-Cookie` / `Content-Length` / `Content-Encoding` not stored, secret fields in text bodies, credentials in URLs). `playApiRecording` FAILS an unmatched request by default (`onMiss: 'fail'`; it never reaches the network; listed in the returned handle's `unmatched`) - `onMiss: 'continue'` is the old fall-through; new `ignoreQueryParams`.
- **`MockServer`** listens on `127.0.0.1`, answers 500 for a throwing handler, and `stop()` drops open connections.
- **curl converter**: `pwd`, `passwd`, `pin`, `otp`, `client_secret`, `x-api-key`, any `cookie` name, XML `<Password>` / `<Secret>` / `<Token>` elements and attributes, and token-like URL path segments are read from the environment; titles no longer contain a path token; bodies that read the environment are getters in CONSTANTS. The command refuses to overwrite an existing spec unless `--force`, and the specs it writes inside a Playwright project read `.env` from that project's folder. The README and the generated header no longer claim secrets are "never written": unrecognised names are written as given - review before committing.
- Tests: `tests/utilsMethods.spec.ts` (re-tested utils, tagged `@smoke`) is replaced by the thin `tests/utilsContract.spec.ts`; recorder tests use per-test files; the OAuth reuse test counts token requests.
- CI: the build job also runs `typecheck`; the `pages` job uses the pinned `allure-commandline` devDependency, checks for Java and for `allure-results`; `.secretscan-allow.json` has an owner and review note; `scripts/setup.*` tell you to clone from your internal Git server.

### Fixed
- `npx api-curl-to-playwright curl/examples.curl` (README, CLI usage, `curl/examples.curl`) failed inside this repo on Windows with "'api-curl-to-playwright' is not recognized": a package's own `bin` is not linked into its own `node_modules/.bin`. The documented command is now `npm run curl-to-tests -- ...`.
- The `clean` script is `rimraf --glob dist "*.tgz"` (Windows did not expand `*.tgz`: "Illegal characters in path"); the first-run table in the README explains the symptom for a checkout that still has the old script.
- Request/response logs in a failed test's attachment masked headers and request bodies but not response bodies, so a login response carrying `access_token` or an echoed password was written to the report; response bodies are masked too.
- **Types:** `MockServer` verb methods and `RouteMockDefinition.body` collapsed to `unknown`, so `(req) => ...` handlers were implicitly `any` under `strict`. Handlers are now typed (`MockBodyFn`, `RouteMockBodyFn`).
